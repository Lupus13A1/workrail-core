# Backend Specification — คู่มือและสารบัญสำหรับทีม Backend (Multi-Tenant Platform)

เอกสารชุดนี้แยกสเปกการพัฒนา **Backend API, Firebase Realtime Database, Firebase Third-Party Auth และ MCP Server** ของแพลตฟอร์ม **Workrail** ออกเป็นไฟล์ย่อยตามหมวดหมู่ เพื่อให้ทีม Backend แบ่งงานและลงมือพัฒนาได้ทันที

## ขอบเขตของแพลตฟอร์ม (Platform Scope)

- **เป็นแพลตฟอร์มแบบ Multi-Tenant มี `Organization / Workspace` (`orgId`) คั่นระดับบนสุด:**
  - ผู้ใช้ 1 คนสามารถสร้างหรือเป็นสมาชิกได้หลาย Organization / Workspace และสลับพื้นที่ทำงานได้
  - ตอนสมัครสมาชิกหรือเข้าด้วย Google ครั้งแรก ระบบสร้าง **Default Organization / Workspace** ให้ทันที (ไม่ต้องกรอกข้อมูลทะเบียนบริษัท และ**ไม่มีระบบคิดเงินค่า Seat / Agent Seat / ใบแจ้งหนี้**)
  - ขอบเขตของ **Project Key** (`APP`, `CLT`), **รายชื่อสมาชิก (`list_people` / `@mention`)**, **การลิงก์การ์ดข้ามโปรเจกต์**, **Agent Accounts** และ **MCP Tokens (`board_pat_...`)** จะถูกแยกตาม `orgId` อย่างชัดเจน ไม่ปนกันข้ามองค์กร
- รองรับ **3 Software Delivery Templates** (`Scrum`, `Kanban`, `Delivery Pipeline`) ตาม `src/lib/project-dashboard.ts`
- ใช้ **Firebase Authentication** (Email/Password + Third-Party Login เช่น Google OAuth) ร่วมกับ **Firebase Realtime Database (RTDB)**
- สิทธิ์ของ AI Agent เท่ากับเจ้าของบัญชีใน Organization นั้นทุกประการ (**User Parity**)
